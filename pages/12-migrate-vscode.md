# Part 1. Cursor 시작하기

## 12. VS Code에서 갈아타기

VS Code를 쓰고 있었다면 Cursor로 옮기는 일은 생각보다 간단하다. Cursor는 VS Code 포크이기 때문에 마이그레이션 기능을 제공한다. 처음 실행할 때 나오는 설정 단계에서 VS Code의 설정을 가져올 수 있다. 설정 파일, 설치된 확장, 키바인딩을 한 번에 이식하는 방식이다.

마이그레이션 순서는 이렇게 진행하면 된다. 먼저 Cursor를 설치하고 로그인한다. 설정 마법사에서 VS Code 가져오기 항목을 찾아 실행한다. 설정이 적용되면, 쓰던 확장이 그대로 설치되어 있는지 확인한다. 키바인딩도 함께 넘어왔는지 몇 개 눌러보면서 점검한다.

확장은 거의 그대로 동작한다. VS Code 마켓플레이스의 확장이 Cursor에서도 설치되기 때문이다. 다만 일부 확장은 Cursor의 AI 기능과 충돌하거나 중복되는 경우가 있다. 예를 들어 별도의 AI 자동완성 확장을 쓰고 있었다면 Cursor의 Tab 자동완성과 겹치니 하나는 끄는 것이 좋다. 둘 다 켜 두면 제안이 두 겹으로 떠서 오히려 불편하다.

설정 파일도 직접 옮길 수 있다. VS Code의 `settings.json`을 열어 내용을 확인한 뒤, Cursor의 설정에 필요한 부분만 복사하면 된다. 전체를 복사하기보다는 편집기 폰트, 탭 간격, 저장 시 포맷 같은 기본 항목 위주로 옮기는 것이 안전하다. AI 관련 항목은 Cursor 설정에서 따로 잡는 것이 낫다.

```json
{
  "editor.fontSize": 14,
  "editor.tabSize": 2,
  "editor.formatOnSave": true,
  "files.autoSave": "onFocusChange"
}
```

이런 식의 기본 설정은 그대로 가져와도 무방하다.

키바인딩은 특히 신경 써야 할 부분이다. 몸에 밴 단축키가 바뀌면 작업 속도가 떨어진다. 마이그레이션으로 가져온 키바인딩이 제대로 동작하는지, 자주 쓰는 명령 몇 가지를 직접 실행해 보면서 확인하자. Cursor 고유 기능의 단축키는 기본값으로 두었다가, 익숙해지면 바꾸는 순서를 권한다.

주의점 한 가지. VS Code와 Cursor를 병행해서 쓰는 사람도 있다. 두 에디터가 같은 프로젝트의 설정 파일을 공유하면 충돌이 생길 수 있으니, 프로젝트별 설정(`.vscode/settings.json`)은 한쪽에만 두는 것이 좋다. 전역 설정은 각자 관리하면 문제가 없다.

갈아타고 나서 처음 며칠은 "VS Code 모드"로 쓰는 것을 권한다. 익숙한 화면에서 익숙한 작업을 하면서, Tab 자동완성 하나씩만 새로 익히는 방식이다. Chat과 에이전트는 그 다음에 천천히 붙이면 된다. 한 번에 다 바꾸려 하면 도구가 아니라 스트레스가 된다.

핵심 정리
- 마이그레이션 기능으로 VS Code의 설정, 확장, 키바인딩을 한 번에 가져올 수 있다.
- 기존 AI 자동완성 확장은 Cursor의 Tab 자동완성과 겹치니 하나만 켜 둔다.
- 처음 며칠은 익숙한 작업 방식 그대로 쓰면서 Tab 자동완성부터 익힌다.
