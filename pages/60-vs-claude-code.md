# Part 6. 선택 주제

## 60. Claude Code와의 비교

AI 코딩 도구가 늘어나면서 "Cursor와 Claude Code 중 무엇을 써야 하느냐"는 질문을 자주 받는다. 두 도구는 모두 에이전트형이지만, 일하는 장소가 다르다. Cursor는 에디터 안에 머무는 에디터형이고, Claude Code는 터미널에서 동작하는 터미널형이다. 이 차이가 선택 기준이 된다.

먼저 공통점부터 정리하자. 둘 다 자연어 지시로 코드베이스를 탐색하고, 여러 파일을 수정하고, 테스트를 돌려 검증한다. 둘 다 승인 과정을 거쳐 변경을 확정하고, 계획-실행-검증의 흐름을 따른다. 기본적인 에이전트 사용법은 한쪽에 익숙해지면 다른 쪽도 빠르게 배울 수 있다.

차이는 작업 환경에서 드러난다. Cursor는 VS Code 계열 에디터를 그대로 쓴다. 기존에 쓰던 확장, 키바인딩, 테마, 디버거 설정이 그대로 이어진다. diff를 보며 승인하는 흐름이 에디터 안에 통합되어 있어, 코드를 눈으로 읽으며 일하는 스타일에 잘 맞는다. 반면 Claude Code는 터미널에서 동작한다. 에디터에 구애받지 않고, 스크립트와 파이프라인 중심의 워크플로에 자연스럽게 녹아든다. CI 환경이나 원격 서버에서 headless로 돌리기에도 터미널형이 편하다.

상황별 선택 기준을 정리하면 다음과 같다.

- 에디터 안에서 diff를 보며 코드를 읽고 승인하는 흐름을 선호한다면 Cursor가 유리하다.
- VS Code 생태계(확장, 설정, 단축키)를 그대로 쓰고 싶다면 Cursor가 자연스럽다.
- 터미널과 스크립트 중심의 워크플로, 자동화 파이프라인에 끼워 넣는 용도라면 Claude Code가 편하다.
- 에디터를 가리지 않고, 여러 환경에서 같은 방식으로 쓰고 싶다면 Claude Code가 유연하다.

실무에서는 둘을 함께 쓰는 조합도 흔하다. 예를 들어 평소 개발은 Cursor에서 하고, 밤새 돌리는 대규모 리팩터링이나 반복 작업은 Claude Code 스크립트로 처리하는 식이다. 도구를 하나로 통일해야 한다는 강박은 버리고, 작업의 성격에 맞게 나누는 것이 생산적이다.

비교할 때 주의할 점도 있다. 첫째, 두 도구 모두 업데이트가 빠르다. 이 책에 적힌 특징은 집필 시점 기준이니, 도입 전에는 각 공식 문서를 확인하자. 둘째, 팀에서 두 도구를 혼용한다면 규칙과 컨벤션은 공통으로 관리해야 한다. .cursor/rules와 Claude Code의 설정이 서로 다르면 같은 팀 안에서 다른 코드가 나온다. 셋째, 비용 구조가 다르니 사용량 기준으로 비교하자. 한쪽이 싸다고 단정하지 말고, 실제 작업 패턴에서의 소모를 측정하는 것이 정확하다.

어떤 도구를 고르든 변하지 않는 원칙이 있다. 에이전트에게 맡기는 작업의 범위를 명확히 하고, 변경은 눈으로 확인하고, 검증은 자동화한다는 것이다. 도구는 바뀌어도 이 원칙은 그대로 통한다.

핵심 정리
- Cursor는 에디터형, Claude Code는 터미널형으로, 일하는 장소가 가장 큰 차이다.
- diff 중심의 에디터 워크플로에는 Cursor가, 스크립트·파이프라인 중심에는 Claude Code가 자연스럽다.
- 하나로 통일하기보다 작업 성격에 맞게 함께 쓰는 조합도 실용적인 선택이다.
