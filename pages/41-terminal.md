# Part 4. 에이전트 모드로 통째로 만들기

## 41. 터미널 자동 실행과 승인

에이전트 모드의 강점은 코드를 고치는 데서 끝나지 않는다. 터미널 명령을 직접 실행해서 의존성을 설치하고, 빌드를 돌리고, 테스트를 실행한다. 이 과정에서 사용자는 어떤 명령이 실행되는지를 확인하고 승인하는 역할을 맡는다.

에이전트가 터미널을 쓰는 대표적인 상황은 세 가지다. 첫째, 새 패키지 설치나 스크립트 추가처럼 설정이 바뀌는 명령. 둘째, tsc, eslint, jest 같은 검증 도구 실행. 셋째, 작업 결과를 눈으로 확인하기 위한 빌드나 서버 구동. 에이전트는 이런 명령을 지시 흐름에 맞춰 필요한 타이밍에 실행한다.

승인 설정은 크게 두 가지 방식으로 운영된다. 하나는 매번 확인하는 방식으로, 명령이 실행되기 전에 사용자에게 승인을 묻는다. 다른 하나는 자동 실행 허용 방식으로, 일정 범위 안의 명령은 묻지 않고 실행한다. 자동 실행은 편하지만 위험한 명령(파일 삭제, 외부 전송 등)이 포함될 수 있어 주의가 필요하다. 기본 원칙은 위험한 명령은 차단하고, 읽기와 검증 위주의 명령부터 자동 실행을 허용하는 쪽으로 시작하는 것이다.

권장하는 초기 설정은 이렇다.

1. 처음에는 매번 확인 모드로 둔다. 에이전트가 어떤 명령을 쓰는지 감을 잡는 기간이다.
2. tsc, npm test, npm run build 같은 검증 명령이 반복적으로 승인 요청을 받으면, 이들을 자동 실행 목록에 추가한다.
3. rm -rf, git push --force 같은 파괴적 명령은 자동 실행에 넣지 않는다. 에이전트가 제안하면 매번 눈으로 확인한다.
4. 명령 실행 후 출력이 길어지면 요약본을 요청한다. "위 출력에서 실패한 테스트만 정리해줘"처럼 말한다.

자동 실행 범위를 좁히는 실무적인 방법도 있다. 프로젝트에 Rules를 두어 "git push는 항상 사용자에게 확인을 받을 것" 같은 규칙을 고정해 두는 것이다. Rules 챕터(50장)에서 자세히 다룬다. 팀 단위로 쓴다면 이 규칙을 저장소에 넣어 공유하면 전원이 같은 기준으로 동작한다.

예시로, 의존성 추가 작업을 에이전트에게 맡겨보자.

```text
날짜 처리에 dayjs를 쓰고 싶어.
npm으로 설치하고, src/utils/format.ts에서 쓰고 있는
Date 직접 계산 부분을 dayjs로 바꿔줘.
바꾼 뒤에는 테스트를 돌려줘.
```

에이전트는 npm install dayjs 실행을 제안한다. 매번 확인 모드라면 이 단계에서 승인을 구하고, 자동 실행 목록에 npm install이 포함되어 있다면 바로 실행한다. 이후 코드 수정과 테스트 실행이 이어진다. 사용자는 중간에 터미널 패널을 열어 실제 실행 결과를 확인할 수 있다.

터미널을 에이전트와 함께 쓸 때 주의할 점은 다음과 같다. 실행 중인 프로세스가 이미 있는 경우(개발 서버가 켜져 있다든지) 포트 충돌이 날 수 있다. 장기 실행 명령(npm run dev 같은)은 백그라운드로 두지 말고 별도 터미널에서 직접 띄우는 것이 깔끔하다. 또한 에이전트가 실행한 명령은 작업 기록에 남으니, 이상한 명령이 실행됐다면 기록을 확인하고 다음 지시에 반영하자.

핵심 정리
- 에이전트는 설치, 빌드, 테스트 같은 터미널 명령을 작업 흐름 안에서 직접 실행한다.
- 승인은 매번 확인에서 시작해 검증 위주 명령부터 자동 실행으로 넓히는 것이 안전하다.
- 파괴적 명령은 항상 눈으로 확인하고, 장기 실행 프로세스는 직접 관리한다.
